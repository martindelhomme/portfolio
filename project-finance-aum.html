01 - Context

A monthly process running entirely on manual work

As part of my role in fund operations at Amundi Canada, a monthly Assets Under Management (AUM) reporting process was performed manually. The workflow involved downloading source files, converting formats, mapping fund and client identifiers, updating reporting templates, and saving the final reports in the correct location.

None of the individual tasks were particularly complex, but the process was repetitive, time-consuming, and required the same manual actions every single month. Any deviation in the source files or naming conventions could introduce errors that were difficult to catch downstream.

"The problem was not complexity, it was repetition. The same sequence of actions, every month, with no value added by doing them manually."
02 - Objective

Reduce manual work without compromising output quality

The goal was to reduce the amount of manual work involved while maintaining exactly the same output and reporting standards. Beyond saving time, I wanted to make the process more reliable and easier to repeat, particularly important in a regulated environment where consistency matters.

A secondary objective was scalability: if reporting frequency increased or new clients were added, the solution needed to accommodate that without significant rework.

03 - Analysis

Mapping the workflow before building anything

Before writing a single line of code, I mapped the workflow step by step to understand where time was actually being spent. This diagnostic phase was the most important part of the project.

The finding was clear: most of the effort was not in analyzing the data itself, but in repetitive operational tasks, retrieving files, renaming documents, converting formats, updating templates, and moving information between sources. Once broken down into smaller steps, it became straightforward to identify which actions could be standardized and automated.

04 - Implementation

Building the solution in VBA

Using VBA, I developed a workflow that automated most of the reporting process end to end. The solution was designed to be maintainable, not just functional once, but easy to update when client lists or reporting requirements changed.

01
Source data import
The tool automatically retrieves the monthly source files from the designated location, handles format conversion, and prepares the data for processing, eliminating the first and most error-prone manual step.
02
Fund and client mapping
A reference table maps fund identifiers to client names and reporting codes. The tool applies these mappings automatically, making it easy to add or update entries without touching the core logic.
03
Template population
The reporting template is populated with the processed data, maintaining the required formatting and structure. No manual copy-paste, no formatting corrections.
04
File naming and saving
Standardized naming conventions are applied automatically at generation. Files are saved to the correct folder structure without manual intervention.
05
Outlook integration and exception handling
One of the more technically involved aspects was integrating with Outlook for distribution, and building robust exception handling, so the tool could flag issues clearly rather than fail silently.

The most challenging aspect was not understanding the process itself, but translating the workflow into a robust technical solution, learning how to interact with Outlook, manage file structures programmatically, and handle edge cases while keeping the tool easy to maintain.

Impact
Monthly AUM reporting reduced from 1-2 hours of manual work to a few minutes of execution time, with improved consistency, easier maintenance, and the scalability to support more frequent reporting if needed.

Beyond the time saved, the process became more consistent. Human error in format conversion, file naming or template population was eliminated. And because the mapping logic is held in a maintainable reference table, adding new clients or adapting to new reporting requirements is a matter of updating a row, not rebuilding the workflow.

06 - Key Takeaway
Understand the workflow before automating it
  • The most valuable part of the project was not the automation itself, but understanding the workflow well enough to simplify it. Once the process was mapped and structured, the technical implementation became a series of solvable problems.
  • In operational finance, the biggest efficiency gains rarely come from analytical complexity, they come from identifying repetitive manual steps and removing them systematically.
  • Building for maintainability matters as much as building for functionality. A tool that works once but breaks when a client is added is not a solution.
  • VBA remains highly effective in environments where Excel is the primary tool, no new infrastructure required, no learning curve for end users, immediate adoption.
